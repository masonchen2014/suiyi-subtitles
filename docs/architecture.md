# 可扩展设计

随译按能力复用功能，网站差异只作为输入层的补充。

```text
HTML5 video / TextTrack ─┐
站点特殊字幕入口 ────────┴→ 统一字幕 {start,end,text}
                           ↓
                    句子与上下文（captions.js）
                           ↓
                    通用预翻译队列和模型层
                           ↓
                    按播放进度显示短字幕
                           ↓
                    共用拖动、位置记忆与状态
```

## 公共层

- `captions.js`：归一化时间轴、句子边界、译文短片段和播放窗口。
- `adapters.js` 的通用控制器：选择标准播放器、读取 TextTrack、优先使用标准能力、提供统一的 `frame(video)`。
- `content.js`：消费统一 frame，处理预翻译、字幕显示、拖动、状态及生命周期，不判断具体网站名称。
- `models.js` / `background.js`：模型协议、凭据、缓存和调用调度，供所有网站复用。

每个 frame 包含当前翻译文本、原文显示片段、当前时间窗口、后续句子，以及是否具有时间轴。是否整句翻译和预加载，由时间轴能力决定，与网站名称无关。

翻译可以读取完整句子，但显示另行按标点与词边界切成短片段，再按句内进度呈现。跨 cue 的句子边界做插值估算，因此不承诺逐词精准对齐。

## 新增视频网站

1. 先确认标准 video / TextTrack 能否提供视频和字幕。能提供时，复用 native 通路，无需新增站点 JavaScript。
2. 在 manifest 中声明明确的网站范围和相应权限。后台来源校验、更新页查找范围从 manifest 读取，避免维护重复域名列表。
3. 只有标准入口无法满足时，注册站点 profile，补充 `load`、`liveText`、`container` 或 `supports`。profile 只返回数据，不实现翻译、缓存、断句或 UI。
4. 用相同公共能力测试新旧站点；只有当前一条字幕时使用实时通路，有完整字幕时间轴时自动获得句子处理和预翻译。

标准通路不代表已授权所有网站：扩展仍只注入 manifest 明确声明的网站。封闭 Shadow DOM、跨域 iframe 或特殊加密播放器可能仍需要单独设计，不能通过复制整个处理流程解决。
